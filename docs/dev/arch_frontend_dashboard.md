# Product Requirement Document: "Scout's Eye" Dashboard

**Status:** DRAFT
**Target System:** React / TypeScript / Vite
**Backend:** FastAPI (Existing)

---

## 1. Executive Summary

We are building **Scout's Eye**, a frontend dashboard for the Football Analytics platform. The primary goal is to visualize the detailed statistical models generated by the **Doppelgänger Engine** (`src/analytics/doppelganger/`).

The interface must transform complex vector embeddings and Z-scores into intuitive **Radar Charts** and **Comparison Tables**, allowing non-technical stakeholders (Scouts, Coaches) to interpret "Player Similarity" without reading JSON.

## 2. Technical Stack Recommendation

To ensure high interactivity and rich data visualization, we will use a Modern Frontend Stack (SPA):

*   **Framework:** React 18 + Vite (TypeScript)
*   **Styling:** Tailwind CSS (for rapid layout) + `clsx`/`tailwind-merge`
*   **Data Fetching:** TanStack Query (React Query)
*   **Visualization:** **Recharts** (best for Radar/Spider charts) or **Tremor** (for KPI cards).
*   **State Management:** Zustand (lightweight global state).
*   **Icons:** Lucide React.

## 3. Core Features & User Stories

### 3.1 The Search Interface
*   **User Story:** As a scout, I want to search for a player by name and season so that I can analyze their performance profile.
*   **Interaction:** Autocomplete input hitting the Player Search API.
*   **Filter:** Dropdown for Season selection (defaults to current).

### 3.2 The Player DNA Radar (The "Visualizer")
*   **User Story:** As a scout, I want to see a player's strengths and weaknesses plotted on a standardized scale so I can quickly assess their playstyle.
*   **Visualization:** A Radar Chart with 3 standardized axes groups (Attacking, Possession, Defensive).
*   **Data Source:** The standardized "Per 90" metrics from `src/analytics/doppelganger/features.py`.

### 3.3 The Similarity Engine (The "List")
*   **User Story:** As a scout, I want to see a list of players statistically similar to my target, including *why* they are similar.
*   **Display:** List of cards. Each card shows:
    *   Similarity Score (e.g., 98%).
    *   "Why this match?" (Shared Strengths / Key Differences text from API).
    *   A "Compare" button to overlay their polygon on the Radar Chart.

## 4. API Integration Specs

The frontend will consume the existing FastAPI endpoints defined in `src/api/routers/`.

| Feature | Endpoint | Method | Response Shape |
| :--- | :--- | :--- | :--- |
| **Search** | `/players/search?name={query}` | `GET` | `[{id, name, position}]` |
| **Get DNA** | `/players/{id}/stats/season/{season}` | `GET` | `PlayerSeasonStats` object |
| **Sim Search** | `/analytics/doppelganger` | `GET` | `DoppelgangerResponse` (Includes explanation) |

**Note:** The backend is running on `http://localhost:8000`. The frontend will run on `http://localhost:5173`. CORS must be configured in `src/main.py`.

## 5. UI/UX Design System (LLM Brief)

*   **Theme:** "Dark Mode Sports Analytics". Deep slates, neon accents relative to performance.
*   **Palette:**
    *   Background: `slate-900`
    *   Card Surface: `slate-800`
    *   Primary Text: `slate-50`
    *   Accent (Attack): `emerald-500`
    *   Accent (Defense): `rose-500`
    *   Accent (Possession): `blue-500`
*   **Typography:** Inter (Google Fonts) or system sans-serif. Monospace for numbers.

### Radar Chart Config
The Radar chart is the centerpiece.
*   **Scale:** Data must be normalized 0-100 (percentiles) or standard deviations (-3 to +3) mapped to canvas coordinates.
*   **Overlays:** Target player is a solid filled polygon (opacity 0.5). Comparison player is a stroked outline (different color).

## 6. Phased Implementation Plan

### Phase 1: Skeleton & Connectivity
*   Initialize Vite + Tailwind project.
*   Create `api.ts` client using `axios` or `fetch`.
*   Build the **Player Search Bar** component that logs the selected Player ID to the console.
*   **Deliverable:** A text box that finds "Harry Kane".

### Phase 2: The "DNA" View (Metrics)
*   Fetch specific player stats using `/players/{id}/stats/season/{id}`.
*   Build `StatCard` components to display raw numbers (xG, Passes, etc.).
*   Implement the **Radar Chart** using Recharts, mapping the raw stats to the axes defined in `src/analytics/doppelganger/features.py`.
*   **Deliverable:** A profile page showing stats and a single-layer Radar chart.

### Phase 3: Similarity & Comparison
*   Fetch similar players using `/analytics/doppelganger`.
*   Render the `SimilarPlayerCard` list.
*   Add state logic: Clicking a similar player adds their data to the Radar Chart as a second series.
*   Display the "Explanation" text provided by the API (Shared Strengths / Key Diff).
*   **Deliverable:** Full functional dashboard allowing "Kane vs Haaland" comparisons.
